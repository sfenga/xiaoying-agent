# 05 复盘

## 1. 最难的问题

**① 冲突判定的"误报"问题(最难)**

最初按"不同文档提取到不同数值即冲突"实现,立刻在两个正常场景翻车:

- 问"每个月吃饭有补贴吗?"会同时召回 D04 餐补(300 元)和 D07 出差伙食补助(100 元)—— 这是**两个不同的福利**,不是冲突;
- 问"那上下班路上的呢?"会召回 D04 交通补贴(200 元)和 D01 市内交通费报销(200 元)—— 同一数值不同性质。

解决方案是三条启发式:标题与问题主题词有交集、单位相同、同单位下数值不同才判冲突,并把"复合问题"(问题本身含 ≥2 个主题词)改为逐一读取覆盖各方面。教训:**判定规则的边界条件要靠"反例测试"驱动**,最终 `test_conflict.py` 的 3 个内容替换用例 + 1 个误报用例就是这些反例的固化。

**② Mock 模型如何"像模型一样决策"**

Mock 不能是真·固定分支(考核明确不认可),它必须消费**观察结果**再决策:检索 0 命中才改写、读到冲突嫌疑才读第二篇、读取失败才换证据源。把它写成"基于步骤观察的无状态策略函数"后,与真实 LLM 共用同一循环接口,也顺带保证了测试确定性。

**③ 引用可信度不能靠约定**

真实模型可能改写原文、虚构 doc_id。因此把"quote 未逐字出现在被引文档 → 剔除 + 记录"做进了循环层(`agent.py::_build_final`),而不是写进提示词祈求模型自觉。`test_dropped_citation_reported` 用一个故意给假引用的坏模型验证了这条防线。

**④ Windows/编码与工程细节**

控制台 GBK 编码、f-string 嵌套引号、pytest 包导入方式等都花了几轮修复;最后统一 UTF-8 输出 + 仓库根 conftest.py 解决。

**⑤ 第二轮增量的三个教训**

- **"确认后收敛"是最容易被忽略的闭环**:冲突场景列完冲突请求确认后,用户回复"按 D01 算"怎么办?直读指定文档看似简单,却连环踩坑:没有"已读守卫"会对同一文档读满步数上限;追问带新主题时,历史主题词在条款打分中会压过新主题——最终用"问题自身主题权重 3 倍于历史主题"解决;
- **测试污染比测试失败更隐蔽**:单测里全局 monkey-patch `requests.post` + `importlib.reload` 想恢复,结果污染了后续所有 HTTP 测试;单文件跑全绿、全量跑全挂。改用 pytest `monkeypatch` fixture(自动还原)后才稳定——集成测试的价值之一就是把这类问题逼出来;
- **"answered 必须有可核验引用"要在循环层收紧**:允许"只有 answer 文本、引用全被剔除"通过,等于给真实模型留了无依据回答的口子;收紧后模型会收到错误反馈并补引用,这才是考核"无依据回答属于关键缺陷"的正确防御姿势。

## 2. 学习收获

- **ReAct 的价值在"观察驱动的分支"**:同一个循环,喂不同观察就长出完全不同的执行路径(改写、深读、恢复、放弃),这比预设流程图的表达力强得多,而且每一步天然可解释、可审计;
- **校验放循环层而不是提示词层**:提示词是"请求",循环校验是"合同";引用逐字核验、状态级约束(answered 必须有依据)这类硬约束放在代码里才能被测试证明;
- **确定性是可测试性的前提**:检索、Mock、工具全部确定性,才能让 72 个测试在 2 秒内离线跑完,让内容替换类测试(替换文档→断言动作变化)成为可能;
- **失败路径和成功路径同等重要**:工具注入故障、步数上限、finish 参数非法这三个"坏路径"共同构成了交付可信度的下半部分。

## 3. 下一步(如果继续做)

1. **接入真实模型跑通全部示例**:配置任一 OpenAI 兼容服务后重跑 demo,针对实际模型的失败模式(输出格式、引用改写)迭代 `SYSTEM_PROMPT` 与解析容错;
2. **检索升级**:文档库扩大后换 BM25(rank-bm25)或本地向量模型(bge-small-zh)+ SQLite/FAISS,保留现有 `Hit` 接口不变;
3. **澄清式追问策略**:现在冲突场景一次列出全部冲突;更自然的做法是按 `applies_to` 元数据先收敛一轮,再就剩余歧义追问;
4. **评测集扩充**:把人工写的"标准动作序列"作为黄金轨迹,加一轮轨迹相似度评测(当前测试只断言最终状态与关键路径特征);
5. **检索规则自动化**:用共现统计从文档自动挖掘别名/同义词候选,减少 rules.json 的人工维护。
