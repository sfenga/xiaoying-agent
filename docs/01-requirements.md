# 01 需求说明

## 1. 用户与目标

**用户**:企业内部员工 —— 需要查找公司制度、福利、流程类问题的可靠答案(如"报销期限多久"、"年假几天"、"餐补多少")。

**目标**:员工用自然语言提问,Agent 基于公司制度/FAQ 文档库给出**可靠、可溯源**的答案:

- 回答必须附带**文档 ID、版本日期与逐字原文片段**,可被人工核验;
- 文档之间规定**冲突**时,不擅自选边,列出冲突并请用户确认适用制度;
- 问题超出资料范围时,如实说明**资料缺口**,不编造;
- 口语化、改写后的相似问题与**上下文追问**(如"那……呢")能被正确处理。

## 2. 输入与材料

| 项 | 说明 |
|----|------|
| 输入 | 用户问题;可选对话历史(多轮追问) |
| 文档库 | 合成制度/FAQ 文档(`data/documents.json`),每篇含 `doc_id`、`title`、`version_date`、`applies_to`(可为空,表示未注明适用范围)、`sections[{heading, text}]`,共 8 篇 |
| 检索规则 | `data/rules.json`:主题词表、口语别名映射、同义词表(仅用于查询扩展,不参与评分) |
| 工具 | ① `search`:文档检索(返回带 doc_id/版本/章节/逐字片段的相关条款);② `read`:按 doc_id(可按章节)读取文档原文 |

## 3. 交付结果

每次问答输出(`AgentResult`,见 `src/kb_agent/schemas.py`):

- **回答**(`answer`)
- **引用**(文档 ID / 版本日期 / 章节名 / 逐字原文片段)
- **冲突**(冲突主题 + 各文档的规定与原文)
- **资料缺口**(`gaps`)
- **任务状态**:`answered` / `needs_confirmation` / `out_of_scope` / `clarification_needed` / `unfinished`(达到步数上限或模型故障)
- **Trace**:每一步的决策依据、工具参数、观察摘要、**后续动作**(观察引发的下一个动作,由循环自动回填)

## 4. 范围

**做**:

- ReAct 决策循环(模型选动作 → 执行工具 → 观察结果 → 模型调整下一步或结束),步数上限默认 8,达到上限返回明确未完成状态;
- 文档检索与片段读取两个工具(纯 Python 实现,支持故障注入);
- 双模型路径:OpenAI 兼容真实模型(配置环境变量即用)+ 离线 Mock 决策策略(标明边界);
- CLI 运行方式(单轮 ask / 多轮 chat / 批量 demo);
- 可执行测试与 6 组验证材料。

**不做**(考核说明明确非必需):图形界面、线上部署、多 Agent 协作、生产级 Runtime、向量数据库。

## 5. 成功标准(对应考核验收点)

| # | 验收点 | 成功标准 |
|---|--------|----------|
| 1 | 明确答案 | 依据命中文档给出答案并附逐字引用 |
| 2 | 文档冲突 | D01(30 天)与 D02(15 天)冲突时:列出双方原文与数值,**不擅自作答**,请求用户确认适用制度;只检索到 D01 且无冲突时可依据 D01 回答 |
| 3 | 资料外问题 | 检索(含改写重试)无命中时返回 `out_of_scope` 并说明缺口,零引用、零编造 |
| 4 | 改写后的相似问题 | 口语化问题(如"工作满一年能休几天假?"→ 年假条款)经查询改写后正确命中 |
| 5 | 上下文追问 | "那上下班路上的呢?"结合上一轮主题(补贴)正确解析为交通补贴问题 |
| 6 | 工具失败 | 注入工具故障后,模型根据错误观察调整动作(改读其他文档/以片段为证),不重复失败动作、不崩溃 |

**通用硬性要求**:所有引用逐字可核验;替换文档内容后答案与动作随之改变;步数上限生效并返回明确的未完成状态。
